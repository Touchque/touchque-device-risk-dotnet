# Changelog

All notable changes to this project will be documented in this file. The
format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [1.1.0] — 2026-11-26

### Added
- **`BotCheckAsync(BotCheckRequest)`** (`POST /device-risk/bot-check`): checks one visitor request for bots from your server, with its address and headers alone, for bots that never run JavaScript (AI assistants, crawlers, curl, scripts). `BotCheckResult` carries `Bot` (`Result`, `Category`, `Provider`, `Name`, `Identity` verified, unverified (a spoofed name) or claimed, `VerifiedBy`, `Confidence`, `Rule`, `Reasons`), `Network` (`Asn`, `AsnOrg`, `CountryCode`, `Hosting`), `Suggestion` (allow, block or challenge: advice in shadow, never enforced) and `RulesVersion`. Values and fields this version does not know are kept as they came (`Raw` holds the whole answer); an answer it cannot read is `not_detected` and `allow`; `DeviceRiskClient.ParseBotCheck` reads an answer. `Authorization`, `Cookie`, `Proxy-Authorization`, `X-Api-Key` and `Set-Cookie` are sent with empty values; the query string and any `user:password@` are removed from `Url`. `HeaderOrderKnown` says whether the headers are in the order the visitor sent them (ASP.NET Core's are not; then they go as one value per name). `HttpVersion` and `Tls` go only when you set them from what your edge saw. What the visitor sent never makes it throw: the first 100 headers go, a name is cut to 128 and a value to 4096 characters, the request is kept under 32 KB, and `truncated` tells Touchque; a header HTTP does not allow, an odd method or a URL Touchque could not read is left out. Only no `Ip` (or one that is not an address), null `Headers` or a header without a name is a `TouchqueConfigException` before any request. Lists `BotResults`, `BotCategories`, `BotIdentities`, `BotVerifiedBy`, `BotConfidences`, `BotSuggestions`, `BotBlankedHeaders` and `BotHttpVersions`.
- `DeviceRiskCheckResult.Visitor["mark"]`: the mark actually applied to the identification (`step_up` always, `trusted` only when the browser matched by its stored key or id, never by traits, else null), in `CheckAsync` and `GetEventAsync`; `DeviceRiskClient.ParseCheck` reads any other value as null (the answer itself is not changed). `status` stays your admin's mark. Absent from older servers.
- **The kind of network** in `Network` (a check, an event, a search row; passed through as it came): `kind` (`residential`, `mobile_carrier`, `education`, `business`, `public_wifi`, `hosting`, `proxy`, `vpn`, `tor`, `relay` or `unknown`: an open list, new values may be added in minor versions; `DeviceRiskClient.NetworkKinds` lists today's), `kindSource` (`address`, `network`, `mixed`, `network_open`, `name`), `vpn`, `shared` with `sharedVisitors24h` and `sharedAccounts24h` ("at least" 1, 2, 5, 10, 100 or 1000) and `lookAlikeMatching`. The docs also name `proxy` and the `relay` type. Search filters `DeviceRiskSearchOptions.NetworkKind` and `Shared`, sent as `networkKind` and `shared=true|false`: `NetworkKind` matches only identifications classified since the field exists, and `Shared = false` only the ones counted and not shared (one that was not counted matches neither). Absent on older servers, which ignore the two filters.
- **AI agents in `Bot`** (the values are plain strings, documented): `tools` may name `claude_agent`, `comet_agent`, `genspark_agent`, `browser_use`, `stagehand` and `skyvern` next to the automation tools, each also a `tool_<name>` reason, and `reasons` may carry `cdp_input`, `input_no_focus`, `insert_text_bulk` and `scripted_click` (`headless_window` and `emulator` are now listed too). The signal `device_ai_agent` also covers an agent's marks on the page. Older servers never send the AI agents or those four reasons.

## [1.0.0] — 2026-11-24

### Added
- **Touchque Device Risk for .NET, its own package** (NuGet `Touchque.DeviceRisk`, namespace `Touchque.DeviceRisk`). Device risk used to live in the main `Touchque` package (`tq.DeviceRisk`); it moves here with the same behaviour. `DeviceRiskClient` signs requests, times out and maps errors exactly like the main SDK (`DeviceRiskOptions`: `ApiKey`, `ApiSecret`, `BaseUrl`, `Timeout`, or `TQ_API_KEY` / `TQ_API_SECRET` / `TQ_API_URL`).
- `CheckAsync(requestId, options)` / `CheckAsync(DeviceRiskCheckOptions)` (`POST /device-risk/check`), `GetEventAsync(requestId)` (`GET /device-risk/events/{requestId}`) and `SearchEventsAsync(DeviceRiskSearchOptions)` (`GET /device-risk/events`), as in the main SDK 5.x.
- **`ActivityAsync(DeviceRiskActivityOptions)`** (`POST /device-risk/activity`): report what a visitor did that your server saw (`payment_attempt`, `login_failed`, `not_found`, `forbidden`, `otp_sent`, `code_failed`), named by `RequestId`, `VisitorId` or `ClientIp`. The answer (`DeviceRiskActivityResult`) carries `Recorded`, `VisitorId`, `PathClass` and the abuse codes raised (`abuse_card_testing`, `abuse_card_shared`, `abuse_login_failures`, `abuse_probing`, `abuse_otp_pumping`, `abuse_code_guessing`). A card is `DeviceRiskCard { Bin, Last4 }`; a full card number is refused with `TouchqueConfigException` before any request.
- `DeviceRiskCheckResult.Suspect` (`DeviceRiskSuspect`: `Score` 0-100, `Band`, `WouldDo`, `Mode` shadow, `Reasons` with `Code`, `Points`, `By`, `Text`) and `DeviceRiskCheckResult.AccountDevice` (`DeviceRiskAccountDevice`: `Status` known, likely, new or first, `VisitorId`, `Since`). `DeviceRiskClient.ParseSuspect` and `ParseAccountDevice` read them from an event or a search row. `matchedBy` may be `fpc` (`DeviceRiskClient.MatchedByValues`).
- `client.Webhook` (`DeviceRiskWebhook`): `Verify` / `VerifyAsync` with a replay cache, and the event names `EventDeviceRiskSignal` (`DEVICE_RISK_SIGNAL`) and `EventDeviceRiskAlert` (`DEVICE_RISK_ALERT`).
